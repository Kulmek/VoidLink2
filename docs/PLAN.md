- Рандеву-сервер + релей, клиенты с Wintun-адаптером, ping между пирами.

## Этап 1 — Идентичность и группы (протокол v2) — ✅ сделано (11.2026)

### 1.1 Идентичность клиента ✅
- При первом запуске клиент генерирует **ed25519 + x25519 пары**, хранит в
  `%APPDATA%\tunnel\client.json` (единый конфиг, не отдельный identity.json).
- **Friend code** — base32 (Crockford, без I/L/O/U) ed25519-pubkey:
  `TUN-XXXX…-…`, 52 символа. Добавление друга = вставка кода
  (`add-friend <code> [alias]`). ✅

### 1.2 Группы ✅
- Группа = отдельная виртуальная сеть, подсеть `100.66.<gid>.0/24`
  (CGNAT, gid 1..254).
- Атрибуты: id, имя, владелец (pubkey создателя), публичная/приватная,
  участники (pubkey → IP), ban-список, инвайты. Управляет владелец. ✅
- **Публичная** — видна всем в списке, вход по желанию. ✅
- **Приватная** — видна только участникам; вход по приглашению владельца
  (`invite <gid> <peer>` → у друга INVITE_RCVD «вас пригласили»). ✅

### 1.3 Выдача IP сервером ✅
- Сервер держит lease-таблицу `pubkey → ip` на группу. Участник при возврате
  получает **тот же IP**. Проверено рестартом сервера и клиентов. ✅
- Клиент IP никогда не выбирает сам; сервер гарантирует уникальность. ✅
- Отклонение от плана: **lease освобождается по leave/kick/delete**, не по
  таймауту офлайна — офлайн-участник сохраняет IP (стабильность важнее). ✅

### 1.4 Шифрование v2 ✅
- В DATA-фрейме dst_ip и group_id в открытом заголовке, payload под AEAD
  ключом группы; релей читает только заголовок (end-to-end даже от сервера). ✅
- Ключ группы генерирует сервер и раздаёт при join по шифрованному каналу. ✅
- Дополнение (не было в плане): HELLO идёт открытым текстом, но **подписан**
  ed25519; ответ WELCOME — открытый (x_pub сервера + подпись ed25519, клиент
  pinned ed-ключ сервера). Дальше весь ctrl-канал шифруется static-static
  X25519. Без этого клиент не мог вывести канальный ключ (не знал x_pub
  сервера), а подмена сессии с чужого IP исключена подписью.

## Этап 4 — TUI (ratatui) — ✅ сделано (11.2026)

```
┌ Группы ─────────────┬ Группа "gamers" (публичная) ─────────────┐
│ ● gamers     3/253  │  имя     IP            связь    ping    │
│ ● work       2/253  │  alpha   100.66.0.2    direct    1 мс    │
│ 🔒 secret    2/253  │  bravo   100.66.0.3    relay     45 мс   │
├ Друзья ─────────────┤                                          │
│ ● alpha (2 группы)  │                                          │
│ ○ charlie           │                                          │
└─────────────────────┴──────────────────────────────────────────┘
 100.66.0.2 @ 127.0.0.1:5555   [F2 создать] [a добавить друга] …
```

- **Группы**: создать (F2), удалить (F8, только владелец), переименовать (F6),
  пригласить друга (i), покинуть, список публичных → войти (j).
- **Друзья**: добавить (a, вставка friend code), удалить (d, с
  подтверждением), Enter по другу → карточка: в каких группах он состоит
  (запрос серверу: публичные группы друга + общие с тобой).
- **Popup'ы**: ввод текста, выбор друга для инвайта, подтверждения.
- **Статус-бар**: мой IP, сервер, счётчик direct/relay.
- **Лог**: последние события (подключения, ошибки) отдельным блоком/вкладкой.

### Что реализовано

- Крейт `tunnel-client` получил подкоманду **`tui`** (alias `ui`) — тот же
  движок, что и `run`, но с графическим интерфейсом; `run` (CLI-лог) сохранён.
- Модуль `crates/client/src/tui/`: `app.rs` (состояние и клавиши), `ui.rs`
  (отрисовка), `theme.rs` (3 темы), `identicon.rs` (аватар по pubkey).
- Движок расширен: `Cmd::ToggleAutojoin`, `Engine::save_config` (правка
  client.json из UI), `Event`-ы уже покрывают всё для тостов.
- Исправлена сломанная сборка HEAD: не хватало `conn_sock_placeholder()`,
  а `engine_loop` не принимал текущий дата-сокет → после реконнекта tun-поток
  писал в старый сокет (потеря трафика до перезапуска клиента).

### Движок под TUI (коммит «Часть 5»)

TUI потребовал от движка постоянного состояния и фоновой работы, а не только
однострочных команд:

- **Потоки**: `engine` (цикл сессии и реконнекта), tun-поток (адаптер →
  сокет), `sampler` (раз в секунду пишет КБ/с в историю для спарклайна,
  60 точек). Состояние для UI — `Engine::groups` / `meta` / `stats`
  (атомарные счётчики байт и пакетов).
- **Состояние групп** (`GROUP_STATE`): участники пересобираются по pubkey с
  сохранением `direct` и RTT; новые и ушедшие пиры → события
  PeerOnline/PeerOffline.
- **Групповые фреймы** (DATA … KEEPALIVE) разбираются в том же цикле, что и
  ctrl: любой фрейм пира, пришедший не через сервер, включает `direct` и
  запоминает его endpoint (событие Direct); PING → ответ PONG, по PONG
  считается RTT; DATA вбрасывается в адаптер.
- **Раунды по таймеру**: RTT-зонд каждому пиру раз в 1 с (direct — напрямую,
  иначе через релей); NAT-раунд раз в 5 с (CTRL_PING серверу +
  PUNCH/KEEPALIVE пирам); список групп раз в 10 с.
- **Сверка** (`reconcile`): группы, которых больше нет в списке сервера
  (удалили/кикнули, пока клиент был офлайн), убираются локально; у только что
  созданной группы 10 с «форы», чтобы её не снесло до прихода списка.
- **Реконнект**: сервер считается потерянным после 20 с тишины. Пауза 1 с →
  2 → 4 … → 30 с; после входа заново отправляются статус, автовход в группы и
  запрос списка. (В этапе 6 потоки и таймеры переделаны — см. ниже.)

### Исправлено после первой версии TUI

- Экран настроек → «Автовход»: Enter переключал группу с gid 0, а не
  выбранную (gid из строки списка не читался). Теперь переключается
  выбранная, список остаётся открытым — можно отметить несколько групп.
- Экран настроек → «Сервер»: выбор только показывал тост и нигде не
  сохранялся. Теперь выбранный сервер ставится первым в `client.json`
  (`run`/`tui` без `--server` берут первый) — применяется после перезапуска;
  текущий сервер отмечен в списке.

- `Home`/`End` шли по кругу (`±1000 mod длина`) и на списке из 7 строк
  `Home` попадал на вторую. Теперь упираются в края.
- Окна профиля, карточки друга и справки были ниже своего содержимого —
  нижние строки (подсказки, последние разделы справки) обрезались. Высота
  теперь считается по содержимому.

### Управление мышью ✅

- Захват мыши (`EnableMouseCapture`); выделение текста терминалом — с
  `Shift`.
- Панель кнопок под шапкой: справка, создать, войти, выйти, пригласить,
  исключить, друг, профиль, настройки, команда, выход. Клик = нажатие
  клавиши — логика одна и та же, что с клавиатуры.
- Клик по строке группы / друга / участника: фокус + выбор; второй клик по
  выбранной строке — `Enter`. Клик по пустому месту панели — только фокус.
- Колесо — прокрутка списка или лога под курсором (без хода по кругу).
- Окна: строки настроек и автовхода — клик применяет сразу; выбор
  участника для invite/kick/ban — только повторным кликом (кик не должен
  случиться от промаха); кнопки `Да`/`Отмена`, `OK`/`Отмена`,
  `Копировать`/`Закрыть`; строка «приватная группа» — переключатель; клик
  мимо окна = `Esc`.
- Как устроено: `ui::draw` каждый кадр пишет геометрию (рамки панелей,
  смещения прокрутки, прямоугольники кнопок) в `App::hits`; `App::hit(x, y)`
  по ней определяет, куда попал клик. Движения мыши разбираются пачкой без
  перерисовки, после клика кадр перерисовывается до следующего события.

### Известные ограничения TUI

- Кик определяется по тексту ERROR от сервера («…кикнут…»/«…забанен…» +

  лучше отдельный фрейм KICKED. ⏳
- Смена сервера — только после перезапуска клиента.

## Этап 6 — Prod: сеть, многопоточность, баги — ✅ (11.2026)

### Найденные баги

- **Бесконечный спам пакетами.** На PUNCH клиент отвечал PUNCH, второй
  клиент — снова PUNCH: пинг-понг без конца, и каждый NAT-раунд (раз в 5 с)
  запускал ещё одну такую цепочку. В e2e-тесте — ~10 000 пак/с на клиента.
  Теперь на PUNCH отвечают KEEPALIVE, на который не отвечают (совместимо со
  старыми клиентами: им KEEPALIVE не отражается).
- **Невозможно выйти из группы.** Таймеры движка (CTRL_PING, раунды)
  срабатывали только на таймауте приёма: при постоянном входящем потоке (тот
  же спам) клиент переставал пинговать сервер, сервер через 30 с снимал
  сессию и молча игнорировал LEAVE. Кроме того, потерянный LEAVE или
  запоздавший GROUP_STATE возвращали группу (и автовход). Теперь таймеры
  идут по часам, LEAVE повторяется до подтверждения, состояния выходящей
  группы игнорируются.
- **Лаги интерфейса** — следствие спама: поток движка обрабатывал тысячи
  пакетов в секунду и на каждый брал мьютекс групп, а UI берёт тот же
  мьютекс на каждом кадре.
- **Длина friend code.** Профиль был уже кода: `friend code: TUN-…` (75
  символов) обрезался рамкой окна, выделенный мышью код был короче 52
  символов. Окна расширены, код — отдельной строкой; разбор терпим к
  пробелам/переводам строк/рамкам/кириллице и сообщает, сколько символов
  получено.
- **Кик не распознавался**: сервер пишет «кикнут», клиент искал «кикнул».
- `--server N` всегда выбирал первый сервер; `del-server N` удалял **все**
  серверы (числовой токен сравнивался сам с собой).
- DATA к пиру без прямого канала уходили на его endpoint (терялись в NAT до
  пробития), а не через релей.
- Длинное имя/статус кириллицей (>255 байт) роняло поток движка (`assert`
  в кодеке строк) — теперь обрезается по границе символа.
- Сервер: после 254 созданий групп нельзя было создать ни одной (gid не
  переиспользовались); повреждённый `server.json` молча заменялся новой
  identity; при входе обнулялся статус участника; кик не обновлял список
  групп кикнутого; сервер не рассылал состояние групп при переподключении
  участника (новый адрес пира узнавали только при следующем JOIN).

### Клиент: потоки

- `rx` — блокирующий приём с единственного сокета; групповые фреймы
  обрабатывает сам, управляющие фреймы сервера передаёт движку. P2P
  работает и во время реконнекта.
- `engine` — состояние соединения, команды UI, таймеры по часам (RTT 2 с,
  PUNCH 5 с, CTRL_PING 5 с, список 15 с, повтор LEAVE 1 с).
- `tun`, `sampler` — как раньше. Сокет один на всё время работы; реконнект
  — новый HELLO с того же адреса.
- `TunDev` — абстракция адаптера: Wintun в проде, заглушка в e2e-тестах.

### Сервер: потоки и защита

- Логика — в `lib.rs` (`Server::start/stop`), `main.rs` — разбор аргументов.
- Воркеры (по числу ядер, 2..8) на одном сокете, состояние под `RwLock`,
  индексы `by_pub` (identity → адрес) и `by_ip` (IP группы → identity):
  релей за O(1) под блокировкой на чтение. Ответы собираются и уходят после
  снятия блокировки.
- Релей: только от сессии, только участнику той же группы, только со своим
  `src_ip`. Лимиты token bucket: релей 4000 пак/с и управление 50/с на
  сессию, HELLO/RESET 5/с на IP. Мусор отбрасывается без записи в лог.
- `RESET` (0x8E, открытым текстом): фрейм от неизвестного адреса → клиент
  сразу шлёт HELLO.
- Сводка раз в 5 минут: сессии, группы, релей пак/с, отброшено.

### Тесты

- e2e в клиенте (`engine_e2e.rs`): сервер + 2 движка на localhost —
  прямой канал, доставка пакета, < 5 пак/с в простое (со старым PUNCH тест
  падает: ~10 000 пак/с), выход без возврата группы, кик, рестарт сервера
  с переподключением < 12 с; посторонний релей → RESET; мусор не роняет
  сервер; битый `server.json` не затирается.
- Сервер (идут и на Linux в CI): выдача gid по кругу, очистка имён, релей
  только своим (подмена `src_ip` отбрасывается), повторный LEAVE,
  сохранение и загрузка состояния.
- Протокол: friend code из буфера обмена, обрезка длинных строк.

## Развёртывание

- **Клиенты — только Windows** (Wintun-драйвер, запуск от администратора).
- **Сервер — Linux**: крейт `tunnel-server` чисто кроссплатформенный (std +
  crypto, без windows-зависимостей). Сборка под Linux: `cargo build --release`
  на хосте или в CI; бинарник + systemd-юнит:

  ```ini
  [Service]
  ExecStart=/opt/tunnel/tunnel-server 0.0.0.0:5555 --data /var/lib/tunnel
  Restart=always
  DynamicUser=yes
  NoNewPrivileges=yes
  ProtectSystem=strict
  StateDirectory=tunnel   # сюда ляжет server.json
  ```
- Правила файрвола на сервере: только UDP-порт (5555) наружу/внутрь.

## Принятые решения

1. **Друзья** — хранятся локально у клиента; сервер не знает список дружб.
2. **Публичные группы** — свободный вход (увидел в списке → вошёл).
3. **Адресация** — `100.66.0.0/16` (CGNAT-диапазон), группа `i` →
   `100.66.<i>.0/24`.
4. **Порядок работ** — сначала протокол v2 + сервер + engine, затем TUI.

## Порядок реализации

1. `protocol v2`: identity (ed25519), friend code, фреймы групп, DATA с
   открытым заголовком (group_id, dst_ip) + AEAD payload.
2. Сервер: группы, lease-таблица IP, персистентность `server.json`,
   инвайты, список публичных групп.
3. Client engine: локальный стор (identity, друзья, автозапуск), мульти-IP
   на адаптере, события для UI.
4. TUI ratatui: экраны Группы/Друзья, popup'ы, статус-бар, лог.
